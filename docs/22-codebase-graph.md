# Development-Time Codebase Graph (Graphify)

## Purpose
Graphify gives Claude Code a persistent structural graph of the repository so architecture and impact questions can be answered from a scoped subgraph before scanning many files.

It is strictly a developer-assistant facility. Production/runtime code must not import or depend on it.

## Two-graph model

| Graph | Owner | Purpose | Data |
|---|---|---|---|
| Graphify | Claude Code/dev tooling | Understand this repository | code, docs, SQL schemas, config |
| Graphiti + FalkorDB | product runtime | Learn from browser/QA executions | pages, actions, failures, playbooks, user stories |

## Bootstrap
Preferred developer-tool install:

```bash
uv tool install graphifyy
```

After Phase 00 creates the initial source skeleton:

```bash
graphify .
```

Do not add Graphify to backend/frontend runtime manifests.

## Repository outputs
Default target:

```text
graphify-out/
├── graph.json
├── GRAPH_REPORT.md
├── manifest.json        # if generated by installed version
├── graph.html           # local visualization; usually ignore
└── cache/               # local speed cache; ignore by default
```

Commit the portable structural outputs when they remain reasonably sized. Ignore generated visualization/cost/cache files unless the team deliberately chooses otherwise.

## Query-before-scan rule
For architecture, dependency and impact questions, query Graphify first when its graph is fresh. Then open only the source files needed to verify implementation details.

Useful patterns:

```bash
graphify query "how is run recovery implemented?"
graphify query "what modules know about Redis?"
graphify path "RunController" "TemporalWorkflowGateway"
graphify explain "ModelRouter"
```

## Refresh policy
Refresh after:
- new bounded context/module;
- new port or infrastructure adapter;
- major schema/workflow changes;
- completed implementation phase;
- significant rename/move/refactor.

Preferred incremental command:

```bash
graphify update .
```

A git hook may be installed later, but the hook must not become a required production/build dependency.

## Failure behavior
Graphify is an optimization, not a source of truth. If it is missing, stale or broken:
1. fall back to source/tests;
2. do not block an otherwise correct implementation;
3. note the skipped graph refresh in HANDOFF;
4. repair Graphify separately if its value justifies it.
